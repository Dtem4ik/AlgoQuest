# AlgoQuest — тренажёр алгоритмов в игровом стиле

> ТЗ для Claude Code. Положи этот файл в корень пустого репозитория и скажи:
> «Прочитай SPEC.md, сначала покажи план Этапа 0 и 1, потом делай по одному этапу».

## 1. Что делаем

Веб-приложение для подготовки к алгоритмическим собеседованиям (LeetCode Top Interview 150) в формате коротких игровых уроков: карта пути, уроки по 3–5 минут, XP, стрики, сердечки, персонаж-маскот, анимированные визуализации алгоритмов.

Главная идея: учим **паттерны** (два указателя, хеш-мапа, скользящее окно и т.д.), а не отдельные задачи. Остров на карте = паттерн, урок = одна задача с LeetCode, разобранная через упражнения.

**Целевой пользователь:** frontend-разработчик, слабый в алгоритмах. Часто учится **с телефона** и не любит печатать код на телефоне. Поэтому:
- **mobile-first**: всё должно идеально работать на экране 375px;
- упражнения решаются **тапами**, без ввода текста с клавиатуры.

Проект пойдёт в портфолио, так что важны чистый код, TypeScript без `any` и аккуратная структура.

## 2. Стек

- **Next.js (App Router) + TypeScript (strict)**
- **Tailwind CSS**
- **Framer Motion** для всех анимаций
- **Zustand + persist** для прогресса в `localStorage`. Бэкенда и логина в MVP нет.
- **Shiki** или **prism-react-renderer** для подсветки кода
- **canvas-confetti** для празднования
- **@dnd-kit** для перетаскивания строк кода (упражнение `order-lines`)
- Деплой: Vercel
- UI на русском. Код, названия задач и термины (two pointers, O(n)) на английском.

## 3. Дизайн

- Яркий, «игровой», дружелюбный. Ориентир — геймифицированные приложения для изучения языков, но **со своей айдентикой**: не копировать чужие логотипы, маскотов и фирменный зелёный.
- Палитра (через CSS-переменные / Tailwind theme):
  - primary — насыщенный фиолетовый `#7C5CFF`
  - success — `#22C55E`, error — `#F43F5E`, xp/золото — `#FBBF24`
  - фон светлый `#F7F7FB`, карточки белые; есть тёмная тема
- Шрифт: **Nunito** (Google Fonts). Крупные жирные заголовки.
- Кнопки «объёмные»: скругление 16px, нижняя тень-«подложка» 4px, при нажатии кнопка опускается на подложку (`translateY(4px)`, тень 0).
- Моноширинный шрифт для кода: **JetBrains Mono**.
- Анимации короткие (150–300ms), пружинные. При `prefers-reduced-motion` анимации отключаются.

## 4. Маскот

Персонаж **Бит**: маленький круглый робот с большими глазами-экранами и антенной. Живёт в углу урока и реагирует на действия.

- Состояния: `idle`, `happy`, `sad`, `thinking`, `celebrate`, `sleepy` (для сломанного стрика).
- На **Этапе 0** нарисовать его как **SVG-компонент** с анимацией: моргание, покачивание, прыжок на `happy`, вздрагивание на `sad`.
- Сделать компонент так, чтобы позже можно было подменить на PNG: `public/mascot/{state}.png`. Если файл есть, берём его, иначе SVG.
- Реплики маскота лежат в данных (массив фраз на каждое состояние, выбираем случайную).

## 5. Экраны

1. **Карта пути (`/`)**
   - Вертикальная извилистая дорожка из кружков-уроков, сгруппированных по островам (паттернам).
   - Статусы урока: закрыт 🔒 / доступен (пульсирует) / пройден ✅ / пройден идеально 👑.
   - Сверху бар: стрик 🔥, XP ⚡, сердечки ❤️.
   - Тап по доступному уроку открывает поповер с названием, номером задачи LeetCode и кнопкой «Начать».
2. **Урок (`/lesson/[id]`)**
   - Сверху: крестик (выход с подтверждением), прогресс-бар, сердечки.
   - Упражнения показываются по одному. Внизу кнопка «Проверить», после проверки появляется плашка: зелёная («Верно!» + объяснение) или красная («Не совсем» + объяснение) и кнопка «Дальше».
   - Ошибка: −1 сердечко, упражнение уходит в конец очереди урока (как в языковых приложениях).
   - Сердечки кончились: экран «Отдохни» с маскотом `sleepy` и кнопкой «Повторить урок».
3. **Итог урока**
   - Конфетти, маскот `celebrate`, полученный XP, точность в %, время, кнопка «Дальше».
   - Ссылка «Решить на LeetCode» ведёт на страницу задачи.
4. **Профиль (`/profile`)**
   - Общий XP, текущий и лучший стрик, календарь активности (как на GitHub), пройденные паттерны.
   - Кнопка «Сбросить прогресс».

## 6. Типы упражнений

Все упражнения — данные (JSON/TS), а не код. Движок урока рендерит их по `type`.

| type | Что видит пользователь |
|---|---|
| `theory` | Карточка с объяснением: текст + опционально код + реплика маскота. Кнопка «Понятно». |
| `visualize` | Пошаговая анимация алгоритма на массиве или строке: ячейки, указатели-стрелки, подсветка, подпись шага. Кнопки «Назад», «Шаг», «Авто». |
| `choice` | Вопрос + 2–4 варианта ответа. |
| `predict-output` | Код + входные данные, вопрос «Что вернёт функция?», варианты. |
| `fill-blank` | Код с пропуском `___`, внизу «плитки»-варианты, тап вставляет плитку в пропуск. |
| `order-lines` | Перемешанные строки решения, собрать правильный порядок перетаскиванием. Отступы показывать по уровню вложенности автоматически. |
| `find-bug` | Код, тапнуть строку с ошибкой. После ответа показать исправленную строку. |

### Визуализатор (самый важный компонент)

`<ArrayVisualizer steps={...} />`:
- ячейки массива — квадраты с значением, над ними индексы;
- указатели — цветные стрелки с подписью (`i`, `k`, `l`, `r`), которые **плавно переезжают** между ячейками (layout-анимация Framer Motion);
- при изменении значения ячейка «переворачивается» или вспыхивает;
- подсветка: `compare` (жёлтая), `write` (зелёная), `skip` (серая), `done` (обведена);
- внизу подпись текущего шага и опциональные переменные (`k = 3`).

Шаги **заранее прописаны в данных урока**, визуализатор только проигрывает их. Строки тоже показываются как массив символов.

## 7. Модель данных

```ts
type PointerName = string; // 'i' | 'k' | 'l' | 'r' ...

interface VizStep {
  array: (number | string)[];
  pointers: Record<PointerName, number>;      // имя → индекс (-1 = скрыть)
  highlight?: Partial<Record<'compare' | 'write' | 'skip' | 'done', number[]>>;
  vars?: Record<string, string | number>;      // показываем под массивом
  note: string;                                // подпись шага
}

type Exercise =
  | { type: 'theory'; title: string; body: string; code?: string; mascot?: MascotState }
  | { type: 'visualize'; title: string; steps: VizStep[] }
  | { type: 'choice'; question: string; options: string[]; correct: number; explanation: string }
  | { type: 'predict-output'; code: string; input: string; options: string[]; correct: number; explanation: string }
  | { type: 'fill-blank'; code: string; options: string[]; correct: number; explanation: string } // в code ровно один ___
  | { type: 'order-lines'; lines: string[]; explanation: string } // lines в правильном порядке, движок перемешивает
  | { type: 'find-bug'; code: string[]; bugLine: number; fixed: string; explanation: string };

interface Lesson {
  id: string;               // 'tp-27'
  title: string;            // 'Remove Element'
  leetcode: { id: number; slug: string; difficulty: 'Easy' | 'Medium' | 'Hard' };
  xp: number;               // 10–20
  exercises: Exercise[];
}

interface Island {
  id: string;               // 'two-pointers'
  title: string;            // 'Два указателя'
  emoji: string;
  color: string;
  summary: string;          // шпаргалка паттерна, показывается после прохождения острова
  lessons: Lesson[];
}
```

## 8. Контент: Остров 1 — «Два указателя»

Порядок уроков (это задачи, которые пользователь уже прошёл с ментором, так что контент должен совпадать с этими объяснениями):

1. **27. Remove Element.** Read/write pointers: `i` читает всегда, `k` пишет только хорошие.
2. **26. Remove Duplicates from Sorted Array.** То же самое, но хорошее число — `nums[i] !== nums[k-1]`. Массив отсортирован, поэтому дубли стоят рядом. Старт `k = 1`.
3. **80. Remove Duplicates II.** Сравнение с `nums[k-2]`, старт `k = 2`, `if (n <= 2) return n`. Обобщение: N копий → `nums[k-N]`. Объяснить, почему `nums[k-1]` лучше, чем `nums[i-1]`.
4. **88. Merge Sorted Array.** Три указателя **с конца** (`i = m-1`, `j = n-1`, `k = m+n-1`), большее пишем в `k`. Цикл `while (j >= 0)`, условие `i >= 0 && nums1[i] > nums2[j]`. Почему с конца: не затираем непрочитанное. Брутфорс: скопировать и `sort((a, b) => a - b)`. Ловушка: `sort()` без компаратора сортирует как строки.
5. **125. Valid Palindrome.** Указатели **навстречу**, пропуск не-alphanumeric через `continue`, сравнение в `toLowerCase()`. Отдельное упражнение `find-bug` про `break` vs `continue`. Хелпер `isAlnum` через сравнение символов `c >= 'a' && c <= 'z'`. Упомянуть вариант с regex, но он O(n) по памяти.
6. **189. Rotate Array.** Брутфорс через `(i + k) % n` и новый массив. Оптимум: три разворота «весь → первые k → остальные», `k = k % n`. Разворот = указатели навстречу + swap (показать и через `temp`, и через деструктуризацию).

### Остров 2 — «Подсчёт и словари» (на Этапе 3)

- **169. Majority Element.** Подсчёт через `Map`, O(n) памяти → голосование Бойера–Мура, O(1). Метафора: «каждый чужой убивает одного нашего».
- **13. Roman to Integer.** Объект-словарь, правило «если текущий < следующего — вычитаем, иначе прибавляем». Почему последний символ не ломает код (`undefined` в сравнении даёт `false`).
- **58. Length of Last Word.** Две фазы — два цикла `while`: сначала скипаем пробелы, потом считаем буквы. Однострочник `trim().split(' ').pop().length` и почему он O(n) по памяти.

### Каждый урок по структуре

1. `theory` — идея паттерна простыми словами (2–4 предложения).
2. `visualize` — прогон на примере.
3. 3–5 практических упражнений разных типов.
4. Последнее упражнение — `order-lines` с полным решением.
5. В итоге урока карточка «Как рассказать на собесе»: брутфорс → оптимум → сложность по времени и памяти.
